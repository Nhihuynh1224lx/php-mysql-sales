# 2026-09-18

## Project onboarding — php-mysql-sales

Read through the whole project to build a mental model.

**Stack:** PHP 8.3 + Apache in Docker (`docker/php/Dockerfile` installs `mysqli`), MySQL 8.4, Bootstrap 5.3 via CDN, Docker Compose.

**Layout:**
- `compose.yaml` — `web` (port 8080 -> 80, mounts `./public` at `/var/www/html` and `./src` at `/var/www/src`), `db` (mysql:8.4, auto-loads `database/schema.sql` then `seed.sql`).
- `public/` — document root; `index.php` + CRUD folders `categories/`, `customers/`, `products/`, `shippers/`, `suppliers/`, each with `index/create/edit/delete.php`.
- `src/config/database.php` — mysqli connection using `getenv('MYSQL_DATABASE'|'MYSQL_USER'|'MYSQL_PASSWORD')`, host hardcoded as `db`, charset utf8mb4.
- `src/includes/` — `header.php` (Bootstrap + TECHSTORE banner), `navbar.php` (nav links), `footer.php`.

**Data model:** categories, suppliers, customers, employees, shippers, products (FK supplier/category, unique ProductCode, CHECK price/stock >= 0), product_images (FK products ON DELETE CASCADE, 1 primary image), orders, orderdetail.

**Conventions observed:**
- Pages require `src/config/database.php` + includes via absolute container paths (`/var/www/src/...`).
- `$pageTitle` set before header include; all output escaped with `htmlspecialchars()`; `number_format()` for VND prices.
- Writes use prepared statements; product create wraps product + images in a transaction with file rollback on failure; uploads validated by MIME via `finfo`, 1–4 files, max 2 MB each, stored as `product-<random16hex>.<ext>`.
- Deletes are POST-only with a JS confirm.
- UI copy is Vietnamese.

**Gaps noticed:** `README.md` is empty; `orders`/`orderdetail`/`employees` have no UI (nav "Đơn hàng" points to `#`); no auth layer; no `.env` in repo (only `.env.example`, ignored via `.gitignore`).

**Working tree:** uncommitted changes — modified `public/products/create.php` plus 6 newly added product images under `public/uploads/products/`.

## UI/UX overhaul + trang chủ dashboard

Rebuilt the whole front-end on top of the existing PHP/Bootstrap stack. No business logic, schema, or routing changed.

**New files**
- `public/assets/css/app.css` (~1600 lines) — design system: tokens, app shell, and Bootstrap 5.3 overrides for table/form/button/badge/alert/card.
- `public/index.php` — rewritten from placeholder to a real dashboard.

**Rewritten**
- `src/includes/header.php` — fonts (Be Vietnam Pro), Bootstrap Icons, app.css, opens `.app-shell`.
- `src/includes/navbar.php` — sidebar with grouped nav + active state derived from `$_SERVER['REQUEST_URI']`, plus topbar (breadcrumb, page title, date, status).
- `src/includes/footer.php` — closes shell, compact footer, mobile sidebar toggle script.

**16 CRUD pages** — `container mt-4` → `page`, page-head with icon/title/subtitle/action, outline action buttons, `.form-actions-inline` bar on create/edit forms.

**Bugs fixed along the way**
- `header.php` never loaded Bootstrap Icons, so every `bi bi-*` icon in `footer.php` rendered blank.
- `categories/create.php` put the `description` value in a *textarea attribute* instead of its content — re-entered text was lost. Also missing `$conn->close()`.
- `categories/index.php` and `products/index.php` had no empty state.
- `products/index.php` used an INNER JOIN on `product_images`, so products without a primary image silently vanished from the list. Homepage uses a correlated subquery instead.
- **Self-inflicted, worth remembering:** I set `overflow: hidden` on `.table-responsive` to get rounded corners. That silently clipped the table and made the Sửa/Xóa column unreachable on narrow screens. Must stay `overflow-x: auto; overflow-y: hidden;`.

**Verification method (reusable)**
No browser automation installed, so used the system Edge in headless mode:
- `msedge.exe --headless=new --screenshot=out.png --window-size=W,H --virtual-time-budget=6000 <url>` for visuals.
- `--dump-dom` + a temporary injected script for real measurements.

Caveat found: `--window-size=412` yields a ~494px layout viewport, so screenshots are **cropped** relative to the layout — a cropped screenshot is NOT evidence of horizontal overflow. Confirmed no overflow properly by comparing `documentElement.scrollWidth` vs `clientWidth` (equal on every page), and verified the table wrapper was genuinely scrollable via a temporary same-origin iframe probe (`public/__probe.php`, since deleted).

## Module Đơn hàng + Nhân viên

Filled in the two modules that had schema but no UI. Sidebar no longer shows "Sắp có".

**New — `public/orders/`**
- `index.php` — list with customer/employee/shipper, item count, order total, plus a 3-card summary strip.
- `create.php` — header fields + dynamic line-item table. Client JS computes line/grand totals from `data-price`; the server **recomputes unit price from the `products` table** and never trusts submitted prices. Validates: date, all three FKs against loaded ID lists, ≥1 line, quantity ≥ 1, no duplicate product. Inserts order + details in one transaction, then redirects to the detail view.
- `edit.php` — same form, prefilled. Save strategy: UPDATE the order header, DELETE all `orderdetail` rows, re-INSERT the submitted list — all in one transaction. Simpler and less error-prone than per-line diffing.
- `show.php` — read-only invoice view: items table with a total row, plus customer and shipping panels.
- `delete.php` — POST-only; `orderdetail` rows go via `ON DELETE CASCADE`.

**New — `public/employees/`** — standard CRUD, avatar initials via `mb_substr`/`mb_strtoupper`.

**New shared pieces**
- `src/includes/helpers.php` — `vnd()`, `format_date()`, `format_quantity()`, each behind `function_exists`. Replaced the `vnd()` that was inlined in `index.php`.
- `public/assets/js/order-items.js` — the line-item table logic, shared by create and edit.

**Verified**
- 28/28 routes return 200 with zero PHP notices; full-tree `php -l` clean.
- Real HTTP test: created an order with 2 items (prices correctly pulled as 8,500,000 and 450,000), confirmed duplicate-product and zero-quantity POSTs were rejected **without** creating rows, edited the order (header + items replaced), then deleted it and confirmed `orderdetail` cascaded to zero orphans. DB back to the 3 seeded orders.
- Confirmed `mbstring` is present in the container, so no Dockerfile change was needed.

**Deliberate omission:** creating an order does not decrement `products.StockQuantity`. Adding that would require restoring stock on edit/delete too; left out to keep the logic simple. Noted in `MEMORY.md`.
